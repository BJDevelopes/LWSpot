# Packaging

LWSpot ships only for Windows, as GitHub releases built by
[`.github/workflows/release.yml`](.github/workflows/release.yml).

## Making a release

1. Set the version in `Cargo.toml` and commit it on `main`.
2. Wait for CI to pass on that commit.
3. Push a tag named after the version, such as `v0.1.0`.

Any tag matching `v*` starts the release workflow. A tag with a suffix, such
as `v0.1.0-rc1`, is published as a pre-release. Pre-releases stay off
"latest", so the app's update check never offers them. Release notes are
generated by GitHub from the merged pull requests; edit them on the release
page if needed. Release tags stay immutable: fix a bad release with a new
version.

## What the workflow builds

The `build` job runs once per target, each on a native runner:

| Target | Runner | vcpkg triplet |
|---|---|---|
| `x86_64-pc-windows-msvc` | `windows-latest` | `x64-windows-static` |
| `aarch64-pc-windows-msvc` | `windows-11-arm` | `arm64-windows-static` |

For each target it:

1. Installs GLEW through vcpkg for libprojectM, sets up the MSVC environment,
   and runs `cargo build --release --locked --target <target>`. Both builds
   include MilkDrop. Release builds never use a compiler cache.
2. Checks that `lwspot.exe` does not import the MSVC runtime DLLs, that it is
   built for the right processor, and that `lwspot.exe --version` prints
   `lwspot X.Y.Z`.
3. Packs a portable ZIP containing `lwspot.exe`, `README.md`, `LICENSE`, and
   `lwspot-portable.txt`. The marker file tells the updater that this copy is
   portable.
4. Builds the installer with Inno Setup from
   [`packaging/windows/lwspot.iss`](packaging/windows/lwspot.iss). The
   installer is per-user: it installs to
   `%LOCALAPPDATA%\Programs\LWSpot\lwspot.exe` with a Start menu entry and
   needs no administrator rights. Its `AppId` must never change, because
   Windows uses it to tell an update from a new program.

The `publish` job then collects both targets' files, writes `checksums.txt`
with their SHA-256 hashes, and creates the GitHub release.

## Release files

Asset names follow the updater's release contract, so do not rename them:

```
lwspot-vX.Y.Z-x86_64-pc-windows-msvc.zip
lwspot-vX.Y.Z-x86_64-pc-windows-msvc-setup.exe
lwspot-vX.Y.Z-aarch64-pc-windows-msvc.zip
lwspot-vX.Y.Z-aarch64-pc-windows-msvc-setup.exe
checksums.txt
```

The in-app updater picks the file for its own architecture and install type
and verifies it against `checksums.txt` before installing. The releases are
not code-signed yet, so SmartScreen may warn on first run.

## Building the installer locally

With Inno Setup 6.3 or later installed, build a release binary and run:

```powershell
cargo build --release
iscc /DVersion=0.1.0 /DArch=x86_64 /DBinary=$PWD\target\release\lwspot.exe /DOutputDir=dist packaging\windows\lwspot.iss
```

`Arch` is `x86_64` or `aarch64`, matching the Rust target triple. CI also
compiles the installer script on every push and pull request to catch syntax
errors.
